# VN30 Liquidity Proxy + SBV Events — Canonical Spec

This spec freezes the two canonical inputs that Phase 44 MacroFilter will consume: `data/vn_liquidity_proxy.csv` (5 yfinance proxy closes merged to a daily panel) and `data/sbv_policy_events.csv` (hand-curated SBV policy-rate actions with inline source citations). It documents the publication-lag policy and the exact `pd.merge_asof(direction='backward')` merge contract that Phase 44 MUST use to guarantee no look-ahead bias.

The research that motivated productionizing these inputs is recorded in `docs/research/liquidity_proxy_correlation.md` (GO verdict: DXY 20d z-score corr = -0.1909, EEM 20d z-score corr = +0.1911 against 20d forward VN30 returns; SBV regime CAGR spread 55.76 pp between easing and tightening windows). That research document is the evidence base; this document is the production contract.

This spec is load-bearing for Phase 44's VAL-04 v6.0 parity regression. Any change to the two CSV schemas, to the regeneration CLI, or to the merge contract MUST be followed by a full re-run of Phase 44 parity tests — the macro filter reads these files as its only source of truth about the VN macro regime.

## Canonical Inputs

### data/vn_liquidity_proxy.csv

| column | dtype | yfinance ticker | description |
|---|---|---|---|
| date | str (ISO YYYY-MM-DD) | n/a | US-market trading date; NaN on days when no US trading occurred |
| usdvnd_close | float | VND=X | USD/VND spot close (24h FX — smoothed managed float) |

Row count at current canonical snapshot: 2867 rows for the default 2015-01-01 → 2026-01-01 range (may drift ±5% as yfinance updates historical data across future regenerations).

NaN policy: NaN is ALLOWED on rows where any column's source market was closed (e.g., US holiday on a VN-open day, or vice versa). The builder does NOT forward-fill at write time — Phase 44 applies its own fill policy on the merged VN30-indexed DataFrame. This keeps the CSV a faithful raw-data record.

Active feature subset per research verdict: only `dxy_close` and `eem_close` 20-day rolling z-scores carry the forward signal. `usdvnd_close`, `tnx_close`, and `vnm_close` are retained in the schema for transparency and possible future research but are NOT consumed by the Phase 44 filter.

### data/sbv_policy_events.csv

| column | dtype | constraint | description |
|---|---|---|---|
| date | str (ISO YYYY-MM-DD) | monotonic non-decreasing | SBV public-announcement date of the rate action |
| rate_change_pct | float | negative for cuts, positive for hikes | Percentage-point change to the policy rate |
| new_refinance_rate_pct | float | >= 0 | New refinance rate level after the action |
| direction | str | {easing, tightening} | easing for any cut; tightening for any hike |
| source | str (CSV-quoted) | non-empty; Reuters / Vietnam News / SBV press / IMF / Vietcombank | Public source citation (publication + date + headline) |

The `neutral` direction value is NOT stored in the CSV. It is DERIVED downstream by Phase 44's 90-day decay rule — any date more than 90 calendar days after the most recent event with direction `easing` or `tightening` is classified `neutral` at the merge time.

Row count at current canonical snapshot: 12 rows per the 43-02 SUMMARY (2017-2023 canonical baseline, 10 easing + 2 tightening). Row count is extensible to ~16 if additional events become verifiable via Reuters, Vietnam News, SBV press, IMF Article IV, or Vietcombank research.

Extension path (ROADMAP success criterion 4): appending a new SBV event is a single CSV line edit — no code change in the builder or in Phase 44. See Section 7.1 for details.

## Regeneration

The liquidity proxy CSV is regenerated by the hardened builder shipped in 43-01:

```bash
uv run python analysis/build_liquidity_proxy.py \
    --start 2015-01-01 \
    --end 2026-01-01 \
    --output data/vn_liquidity_proxy.csv \
    --max-retries 3 \
    --retry-backoff-sec 5.0
```

Flags and defaults (all 5 flags are locked under D-03):

- `--start YYYY-MM-DD` (default `2015-01-01`) — inclusive start date
- `--end YYYY-MM-DD` (default `2026-01-01`) — exclusive end date
- `--output PATH` (default `data/vn_liquidity_proxy.csv`) — output CSV path
- `--max-retries N` (default `3`) — max retry attempts on transient yfinance errors
- `--retry-backoff-sec S` (default `5.0`) — base backoff seconds; sleep = base * 2**attempt

Running with NO flags regenerates the canonical CSV end-to-end.

Retry policy (D-04): HTTP 401, 403, 429, `ConnectionError`, `Timeout`, and empty-DataFrame responses (a silent yfinance rate-limit surrogate) trigger exponential-backoff retries up to `--max-retries` attempts. Other HTTP status codes (e.g., 500) re-raise immediately — different failure class, not a rate-limit.

Missing-column errors (D-05): if yfinance returns a DataFrame without a `Close` column (or a MultiIndex without a `Close` level), the builder raises `RuntimeError` naming the ticker — these errors are NEVER silenced. If the builder fails with this error class, the `yfinance` version has drifted relative to what this spec was validated against and MUST be pinned or upgraded in `pyproject.toml` before regeneration.

Exit codes: 0 on success; non-zero with `RuntimeError` on exhausted retries or schema break.

The SBV events CSV is NOT regenerated by a script — it is hand-curated per plan 43-02 with an inline source citation per row. Appending a new event is a one-row append; no code path executes.

## Publication-Lag Policy

This is the load-bearing section. The policy documented here is what Phase 44 MUST encode in its merge step to avoid introducing look-ahead bias. Policy follows D-08.

### DXY / EEM / VNM (US-market yfinance tickers)

- The US cash session closes at approximately 22:00 ICT (UTC+7) during US DST (March-November), and at approximately 23:00 ICT in US winter.
- The VN session has already closed for the day (VN session runs 09:00-14:45 ICT).
- The first VN trading session that can use the US close of date D is the NEXT VN trading day (D+1, or later across weekends / holidays).
- Because the CSV stores the US-local close date, `pd.merge_asof(direction='backward')` on VN30 trading dates naturally applies a 1-VN-trading-day lag — the US close row for date D is matched to the VN session on D+1 via the backward join.
- NO manual date shift is required for DXY / EEM / VNM. The natural backward-merge behavior is correct.

### TNX (US 10Y yield)

- Same US-market timing as DXY / EEM: US close → VN next session via backward merge.
- TNX is excluded from the active feature set per the research verdict (near-zero 20d-forward z-score correlation) but retained in the CSV schema for transparency.

### USD/VND (VND=X — 24h FX)

- USD/VND trades 24 hours globally and is continuously quoted during the VN session.
- Same-day availability is technically possible.
- USD/VND is excluded from the active feature set per the research verdict (correlation near zero). It is retained in the schema for transparency and future research.
- If a future Phase 44 variant ever consumes USD/VND, it MUST still use `pd.merge_asof(direction='backward')` for consistency with the DXY / EEM treatment — do not special-case FX to a forward or exact-match merge.

### SBV policy events

- SBV policy-rate announcements are typically intra-session VN press releases (morning or afternoon).
- A signal derived from an SBV announcement on date D is NOT available to trade on the same session — the first VN session that can act on the announcement is the NEXT VN trading day (T+1).
- Merge contract: shift event dates by +1 business day to build an `effective_date` column, then `merge_asof(direction='backward')` on `effective_date`:

```python
sbv['effective_date'] = sbv['date'] + pd.tseries.offsets.BusinessDay(1)
merged = pd.merge_asof(
    vn30.sort_values('date'),
    sbv.sort_values('effective_date'),
    left_on='date',
    right_on='effective_date',
    direction='backward',
)
```

- The 90-day decay from the most recent `effective_date` to `neutral` is applied AFTER this merge in Phase 44's classifier, not in the CSV.

## Merge Contract (for Phase 44 MacroFilter)

This is the exact contract Phase 44 MUST implement. Any deviation from these signatures invalidates the no-look-ahead guarantee documented above.

### Proxy merge

```python
proxy = pd.read_csv('data/vn_liquidity_proxy.csv', parse_dates=['date'])
vn30 = load_vn30_dataframe()  # date-indexed

merged = pd.merge_asof(
    vn30.sort_values('date'),
    proxy.sort_values('date'),
    on='date',
    direction='backward',
    allow_exact_matches=True,
)
```

- `direction='backward'` is MANDATORY. `direction='forward'` or `direction='nearest'` would let VN decisions peek at future US closes and would invalidate the no-look-ahead guarantee.
- `allow_exact_matches=True` permits same-date rows to match on days when US and VN markets both had a session (e.g., both open on a Monday with no holiday on either side).
- Both sides MUST be sorted by `date` before the merge — `merge_asof` requires monotonic keys.

### SBV merge

See the code block in Section 4.4 (Publication-Lag Policy → SBV policy events). Key points:

- SBV event dates MUST be shifted by `+1 BusinessDay` to build an `effective_date` column BEFORE the merge.
- `merge_asof(direction='backward')` is run on `effective_date`, not on the raw `date` column.
- After the merge, apply 90-day decay: any VN30 date more than 90 calendar days after the most recent `effective_date` is classified `neutral`. This decay is Phase 44's responsibility, not the CSV's.

### Z-score computation

- DXY and EEM 20-day rolling z-scores MUST be computed on the MERGED DataFrame (VN30-date-indexed), NOT on the raw proxy CSV.
- Computing the z-score on the proxy CSV directly would produce a z-score indexed by US trading days. Mapping that back to VN30 dates via merge would silently use the nearest US date's z-score for a given VN date, which can be a future date from the VN perspective when the US session runs on a day the VN market is closed.
- Computing the z-score AFTER the backward merge ensures the rolling window respects VN30 trading-day ordering and skips VN holidays naturally.

## Look-Ahead Traps Ruled Out

Per D-09, the following traps MUST be ruled out by the contract above. Any future change to the merge or to the CSVs that reopens one of these traps requires a full re-run of Phase 44 VAL-04 parity tests and Phase 46 OOS validation.

1. **Same-day DXY / EEM merge is FORBIDDEN.** `merge_asof(direction='forward')` or `direction='nearest'` on same-date DXY / EEM close would let VN decisions made at 09:00 ICT peek at the US close that happens roughly 13 hours later that same calendar day. `direction='backward'` is the only correct choice for these tickers.

2. **SBV intra-session announcement lag.** If an SBV rate hike is announced at 14:00 ICT on date D, a VN30 SELL signal firing on date D at 09:30 ICT MUST NOT use the new `tightening` regime tag for that day's decision — the announcement had not yet occurred. The `effective_date = event_date + 1 BusinessDay` shift documented in Section 4.4 enforces this — the regime tag only becomes visible starting from D+1.

3. **Weekend / holiday bridging is naturally correct under `merge_asof(direction='backward')`.** If Friday's US close is the last proxy row and the VN market is open Monday while the US is closed Monday (e.g., Presidents' Day), VN Monday's merge picks up Friday's US close — correct, because no Monday US close exists yet. Last-known-value carry is the INTENDED behavior. The CSV MUST NOT be forward-filled at write time — that would fabricate proxy values on non-US-trading days and corrupt the raw-data contract.

4. **Rolling z-score computed on the raw proxy DataFrame is WRONG.** Computing a 20-day z-score on the proxy CSV directly would produce a series indexed by US trading days. Mapping that series back to VN30 dates via any merge could silently use a z-score value from a US date that lies in the FUTURE from the VN date's perspective (when the nearest US date is tomorrow). The z-score MUST be computed on the merged VN30-indexed DataFrame AFTER the backward merge.

5. **SBV `direction='nearest'` is FORBIDDEN.** Using `direction='nearest'` on the SBV merge would match a VN date to a FUTURE SBV event (when that future event is closer in calendar distance than the most recent past one). Only `direction='backward'` on the shifted `effective_date` column is correct.

## Extension Path

Both canonical inputs are designed for single-row-edit extension without code changes, per ROADMAP success criterion 4.

### Adding a new SBV event

1. Append a single row to `data/sbv_policy_events.csv` with the 5 columns `date,rate_change_pct,new_refinance_rate_pct,direction,source`.
2. Ensure `direction` is `easing` or `tightening` — never `neutral` (neutral is derived downstream by the 90-day decay rule).
3. Ensure `source` cites a public primary source (Reuters, Vietnam News, SBV press release, IMF Article IV, Vietcombank research). Format: publication + date + short headline; URL is optional.
4. Ensure `date` keeps the file monotonic non-decreasing (append at the end for a new event, or insert and re-sort if a backfill event predates existing rows).
5. No code change. Phase 44 picks it up on the next run.

### Regenerating the liquidity proxy for a new date range

1. Run the builder with custom `--start` and `--end` flags (e.g., to backfill to 2014 if a future phase extends the VN30 history window).
2. The output CSV overwrites the existing file. Git history tracks every regeneration via the CSV diff.
3. Phase 44, 45, and 46 regression tests MUST be re-run after any regeneration that changes the date range — z-score computations and SBV regime tags are date-range-sensitive, and VAL-04 v6.0 parity depends on deterministic inputs.

### Changing the yfinance ticker set

Changing the tickers downloaded by the builder is NOT a simple CSV edit. Ticker changes modify the builder's `TICKERS` dict, break the 6-column schema contract, and require all of:

1. Update this spec's Section 2.1 schema table to reflect the new column set.
2. Re-run the Phase 44 VAL-04 parity regression — signal logs may change.
3. Obtain a new milestone-level decision. A ticker change is a canonical-input-contract break, not a Phase 43 maintenance edit.
