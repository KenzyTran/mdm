# Phase 999.1 Plan 01: MDM SELL RS-Ranked Partial Liquidation Summary

**One-liner:** RS-ranked partial liquidation for MDM SELL — top 50% retained by RS (configurable via `sell_retain_pct`), NaN RS treated as weakest, ceil-based retention count.

## What Was Built

### PortfolioConfig (`strategies/portfolio/config.py`)
- Added `sell_retain_pct: float = 0.5` field with docstring
- Added validation: `if not (0 < self.sell_retain_pct <= 1): raise ValueError(...)` (0 excluded, 1.0 included)

### PortfolioEngine (`strategies/portfolio/engine.py`)
- Added `_sell_retained_ids: set = set()` to internal state (initialized in `__init__`)
- Replaced full liquidation SELL block with RS-ranked partial liquidation:
  - Builds `already_scheduled` set of positions already queued for `mdm_sell`
  - Builds `eligible` list excluding already-scheduled AND already-retained positions
  - Computes `n_keep = math.ceil(len(eligible) * self.cfg.sell_retain_pct)`
  - Sorts eligible by RS descending (NaN/None → `-inf`)
  - Top `n_keep` positions added to `_sell_retained_ids`
  - Bottom positions scheduled for `mdm_sell` exit at next bar open
- Modified section 4 (`evaluate_exits` loop) to skip positions in `_sell_retained_ids`
  - This prevents retained positions from being re-closed via the exit chain's own SELL dispatch

### Tests (`tests/strategies/portfolio/test_gate_policy.py`)
- Added `_make_inputs_with_varied_rs` helper (4 tickers, RS=[90,80,60,40], `rs_threshold=0`)
- Added 5 new tests:
  - `test_sell_retains_strongest_by_rs`: T60+T40 closed, T90+T80 retained
  - `test_sell_retain_pct_configurable`: 0.75 keeps 3, 0.25 keeps 1
  - `test_sell_nan_rs_treated_as_weakest`: NaN RS evicted first
  - `test_sell_retain_rounds_up`: 3 positions + 0.5 = ceil(1.5)=2 retained, 1 closed
  - `test_sell_retain_pct_validation`: 0.0 raises, -0.1 raises, 1.1 raises, 1.0 valid
- Updated `test_policy_a_sell_liquidates_all`: 2 tied-RS positions, 1 retained, 1 closed

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Retained positions were re-closed by evaluate_exits SELL dispatch**
- **Found during:** Task 2 GREEN phase
- **Issue:** `evaluate_exits` (section 4) also dispatches `mdm_sell` for any position when `mdm_state == "SELL"`. Without a guard, retained positions were immediately re-scheduled via section 4 even after being excluded from section 3's liquidation block.
- **Fix:** Added `if id(pos) in self._sell_retained_ids: continue` guard in section 4 before calling `evaluate_exits`.
- **Files modified:** `strategies/portfolio/engine.py`
- **Commit:** 816d9bf

**2. [Rule 2 - Missing test precondition] rs_threshold=0 needed in test helper**
- **Found during:** Task 2 GREEN phase
- **Issue:** Test tickers T60 (RS=60) and T40 (RS=40) were being closed by `rs_deterioration` before bar 35 SELL fired, because `rs_threshold=70` was the default. The test intended to test SELL-driven partial liquidation but positions weren't alive at SELL time.
- **Fix:** Added `rs_threshold=0.0` to `_make_inputs_with_varied_rs` cfg and `test_sell_nan_rs_treated_as_weakest` cfg to disable RS-deterioration in these specific tests.
- **Files modified:** `tests/strategies/portfolio/test_gate_policy.py`
- **Commit:** 816d9bf
