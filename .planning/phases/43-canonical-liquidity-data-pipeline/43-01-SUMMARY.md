## Decisions Made

See `key-decisions` frontmatter. Summary of the two non-obvious ones:

- **Empty-DataFrame → `ValueError` → retry branch**: yfinance will sometimes silently return an empty frame on rate-limit rather than throwing HTTP 429. Promoting this to a `ValueError` inside the try body and then letting the `ValueError` handler classify it as transient means a single retry path covers both overt 429s and silent rate-limits.
- **Missing-column guard in BOTH code paths**: MultiIndex and flat columns are handled separately with distinct error messages. Earlier (quick-task) version used `df['Close']` on the flat path which would throw `KeyError`, not `RuntimeError`. Converting to an explicit presence check + raised `RuntimeError` gives Phase 44 a single, greppable error class (`RuntimeError`) to key off.

## Issues Encountered

- **Smoke-test path portability**: Plan verification step 1 uses `--output /tmp/proxy_smoke.csv`. On Windows, the script correctly resolves `/tmp` to `C:\Users\trant\AppData\Local\Temp` via Python `pathlib`, so the CSV was written successfully (`Wrote 262 rows to C:\...\proxy_smoke.csv`). However, the follow-up pandas `read_csv('/tmp/proxy_smoke.csv')` does NOT auto-resolve on Windows, so a parallel read at the Windows TEMP path was used instead. Non-blocking — future Phase 44/45 shell-outs should either use absolute Windows paths or `$env:TEMP` directly to avoid this cross-platform gotcha.
