    STATE_TO_SIGNAL dict mapping per D-01:

    def extract_model_signals(results_df: pd.DataFrame) -> pd.DataFrame:
        Map results_df['state'] via STATE_TO_SIGNAL. Detect transitions where mapped signal != previous row's mapped signal. Return transitions[['date', 'signal']].reset_index(drop=True). Per D-01.

    def align_signals(model_signals: pd.DataFrame, published_signals: pd.DataFrame) -> pd.DataFrame:
        Outer merge on 'date' column. Rename model's signal to 'model', published's signal to 'published'. Sort by date. Return DataFrame[date, published, model].

    def compare_signals(model_signals: pd.DataFrame, published_signals: pd.DataFrame) -> dict:
        Align signals. For each published signal row, check if model has exact same signal on exact same date (per D-02). Compute overall match_rate = (matched / total_published) * 100. Compute per_type breakdown for Buy/Sell/Cash per D-03. Return dict with keys: match_rate, total_published, total_matched, per_type.

    def classify_divergences(aligned_df: pd.DataFrame, model_signals_df: pd.DataFrame, engine_results_df: pd.DataFrame, config: MDMConfig) -> pd.DataFrame:
        For each row in aligned_df where published != model (a divergence):
        1. TIMING FIRST: Check model_signals_df for same signal type as published within +/-5 trading days -> 'TIMING' (per D-06, Pitfall 5: must match same type). This applies to ALL signal types including Cash.
        2. If published == 'Cash' AND no model Cash transition found within +/-5 days -> 'STRUCTURAL' (per D-06, structural impossibility -- model has no nearby Cash transition at all)
        3. Check engine_results_df on that date: if dd_count >= config.dd_window_size - 1 (within 1 of threshold), or if abs(row's price_change_pct) >= config.ftd_min_price_gain * 0.9 (within 10%), or drawdown_pct within 10% of correction_threshold -> 'THRESHOLD'
        4. Else -> 'IRREPRODUCIBLE'
        Return aligned_df with added 'divergence_type' column (NaN for matches).

        IMPORTANT: Step 1 (TIMING) must be checked BEFORE step 2 (STRUCTURAL). Per issue #5, when the model DID produce a Cash transition nearby, that is a TIMING divergence, not STRUCTURAL. STRUCTURAL is reserved for cases where the model has NO Cash transition within the window at all.

    def generate_divergence_context(row, engine_results_df, config) -> str:
        For each divergence row, produce a short context string explaining why it was classified that way. E.g., "TIMING: model Buy on 2019-05-09 (2 days late)" or "STRUCTURAL: published Cash, model has no deliberate Cash signal". This feeds the 'context' column in the CSV per D-07.
