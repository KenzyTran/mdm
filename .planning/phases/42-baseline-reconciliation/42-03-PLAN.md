    1. **Save current branch state** (to restore after bisect):
       ```bash
       CURRENT_BRANCH=$(git rev-parse --abbrev-ref HEAD)
       HEAD_HASH=$(git rev-parse HEAD)
       ```

    2. **Initialize bisect** with the pinned anchors from `docs/audits/v10_baseline_drift.md ## Bisect Endpoints`:
       ```bash
       SHIP=$(grep -oE '[a-f0-9]{40}' docs/audits/v10_baseline_drift.md | head -1)  # good anchor
       git bisect start
       git bisect bad $HEAD_HASH
       git bisect good $SHIP
       ```

    3. **Run bisect with the gate script**, tee-ing output to a log file:
       ```bash
       git bisect run uv run python analysis/bisect_v10_baseline.py 2>&1 | tee /tmp/bisect_run.log
       ```

       Bisect will automatically converge on the first "bad" commit. Git writes per-step output with lines like:
       - `Bisecting: N revisions left to test after this (roughly M steps)`
       - `[<hash>] <subject>` (commit being tested)
       - The script's `BISECT_RESULT: cagr=... sell=... max_dd=...` line
       - `$ git bisect good` or `$ git bisect bad`

    4. **Parse the bisect log** into a list of (commit_hash, cagr, sell, max_dd, verdict) tuples. For each commit tested:
       - Extract hash from the `[<hash>] <subject>` line
       - Extract cagr, sell, max_dd from the next `BISECT_RESULT:` line
       - Determine verdict from subsequent `git bisect good/bad/skip` line
       - For commits the script reported exit 125 (SKIP), verdict = "skip (untestable)"

    5. **Look up commit metadata** for each tested commit:
       ```bash
       for HASH in $TESTED_COMMITS; do
         git show -s --format='%H|%ai|%an|%s' $HASH
       done
       ```
       Split by `|` into (full_hash, iso_date, author_name, subject).

    6. **Append to `docs/audits/v10_baseline_drift.md`** — replace the `_To be populated by plan 42-03._` line under `## Bisect Log` with a markdown table:

       ```markdown
       | <short_hash> | <YYYY-MM-DD> | <author> | <subject> | <cagr> | <sell> | <max_dd> | good / bad / skip |
       | ... | ... | ... | ... | ... | ... | ... | ... |

       **Offending commit identified by bisect:**

       `<short_hash>` — `<subject>`

       Full hash: `<full_hash>`
       Date: `<YYYY-MM-DD>`
       Author: `<author>`

       This is the commit where `uv run python analysis/bisect_v10_baseline.py` first returns exit 1 (CAGR < 11.4%).
       Its immediate parent returned exit 0 (CAGR >= 11.4%).

       CAGR delta at this commit: `<cagr_before> - <cagr_after> = <delta>pp`
       SELL count delta: `<sell_before> - <sell_after> = <delta>`
       MaxDD delta: `<maxdd_before> - <maxdd_after> = <delta>pp`

       **Diff summary:** `git show --stat <full_hash>` attached below:

       ```
       <output of git show --stat>
       ```

       **If bisect identified multiple non-monotone drift commits (per D-05):** each additional commit is listed in a
       separate row below, with per-commit impact measured by re-running bisect on segments.
       ```

    7. **If bisect reports multiple drift segments** (non-monotone CAGR trajectory — some commits may restore CAGR then lose it again): after the first bisect converges, inspect the full per-commit log. If any "good" commit (between good-anchor and first offending commit) is actually below 11.4% (script skip or exit 1), document as a secondary drift.     8. **Write the Root-Cause Narrative** under `## Root-Cause Narrative`, replacing the `_To be populated by plan 42-03._` line with a narrative covering:

       - Whether the change touches fail-safe logic (per D-11, if yes → this triggers accept-and-document path, not revert)
