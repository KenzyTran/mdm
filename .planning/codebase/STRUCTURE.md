## Directory Purposes

**models/**
- Purpose: Market Direction Model (MDM) - single-asset VNINDEX trading strategy
- Contains: Strategy components (data, indicators, signals, position management) and orchestration
- Key files: `mdm_engine.py` (orchestrator), `config.py` (parameters), `position_manager.py` (state machine)
- Usage pattern: Components are imported and composed inside MDMEngine for daily bar processing
- Backtest entry: `run_backtest.py` uses this module

**vn30_vsa/**
- Purpose: Volume Spike Analysis (VSA) - multi-stock portfolio strategy for VN30 components
- Contains: Portfolio-level backtesting (5+ stocks simultaneously), Kelly position sizing
- Key files: `vsa_engine.py` (orchestrator), `position_manager.py` (portfolio manager), `kelly.py` (sizing)
- Usage pattern: Handles per-stock data dict + portfolio-level accounting
- Backtest entry: `vn30_vsa_backtest.ipynb` notebook uses this module

**analysis/**
- Purpose: Post-backtest analysis and diagnostics
- Contains: Utility scripts for deep-diving into strategy performance
- Key files: `diagnose_vn30.py` (VN30 specific analysis)
- Usage: Run after backtest to understand specific issues or validate assumptions

**Root Python files:**
- `run_backtest.py`: MDM strategy backtest execution (loads data → runs engine → outputs report)
- `optimize_mdm.py`: Parameter grid search for MDM (iterates configs → compares results)
- `check_date.py`: Date format validation utility
- `analyze_drawdown.py`: Drawdown analysis for MDM results
- `analyze_vsa_drawdown.py`: Drawdown analysis for VSA results

**Notebook files:**
- `mdm_backtest.ipynb`: Interactive MDM experiments (parameter tuning, visualization)
- `vn30_vsa_backtest.ipynb`: Interactive VSA experiments (multi-stock backtesting)
- `sp500_backtest.ipynb`: Experimental S&P 500 variant (may be incomplete)

## Key File Locations

**Entry Points:**
- `run_backtest.py`: Executes MDM backtest, writes report.txt
- `optimize_mdm.py`: Runs parameter grid search optimization
- `vn30_vsa_backtest.ipynb`: Interactive VSA backtesting
- `mdm_backtest.ipynb`: Interactive MDM backtesting

**Configuration:**
- `models/config.py`: MDMConfig dataclass with strategy parameters (correction_threshold, ftd_min_rally_day, stop_loss_pct, etc.)
- `vn30_vsa/config.py`: VSA configuration constants (VOLUME_SPIKE_MULTIPLIER, MAX_POSITIONS, POSITION_WEIGHT, KELLY settings)
- `pyproject.toml`: Project metadata, Python version requirement (>=3.10), dependencies list

**Core Logic:**

*MDM Strategy:*
- `models/mdm_engine.py`: Main orchestration - loads data, calculates indicators, runs daily processing loop
- `models/position_manager.py`: State machine (CASH → HOLDING → WAITING_SELL → SHORT)
- `models/ftd_signal.py`: Follow-Through Day detection logic
- `models/rally_attempt.py`: Correction phase and rally day tracking
- `models/distribution_day.py`: Distribution day detection and counting

*VSA Strategy:*
- `vn30_vsa/vsa_engine.py`: Multi-stock portfolio backtesting orchestration
- `vn30_vsa/position_manager.py`: Portfolio-level position tracking for 5+ stocks
- `vn30_vsa/signals.py`: Volume spike and breakout detection
- `vn30_vsa/kelly.py`: Dynamic position sizing via Rolling Kelly Criterion

**Testing:**
- No dedicated test directory - validation is in Jupyter notebooks
- Interactive testing: Run cells, inspect results, visualize charts

**Data Files:**
- Input: `vnindex_price.csv`, `vn30_price.csv` (expected in project root)
- Output: Generated during backtest runs (e.g., `optimization_results.csv`, `report.txt`)

## Naming Conventions

**Files:**
- Strategy modules: `{strategy_name}_engine.py` (mdm_engine.py, vsa_engine.py)
- Component modules: Descriptive noun form (indicators.py, position_manager.py, signals.py, stop_loss.py)
- Utility scripts: Verb + subject (run_backtest.py, analyze_drawdown.py, check_date.py)
- Configuration: `config.py` in strategy directories

**Directories:**
- Strategy containers: Snake case, concise (models, vn30_vsa)
- Utility container: General noun (analysis)
- Dotfiles: Prefix with period (.planning, .git, .env)

**Classes:**
- PascalCase for all classes: DataLoader, Indicators, MDMEngine, PositionManager, MarketState
- Enum subclasses: SCREAMING_SNAKE_CASE for values (CASH, HOLDING, WAITING_SELL, SHORT)
- Exception handling: Return type-safe pairs (is_condition, Signal or None) instead of exceptions

**Functions:**
- Snake_case throughout: add_price_location_column(), check_ftd(), get_trades()
- Static methods in utility classes: Indicators.add_ma50_column()
- Config getters: get_* pattern (get_state(), get_buy_price(), get_trades())

**Variables:**
- Snake_case for all variables: daily_change, buy_price, is_ftd, dd_count
- Constants: SCREAMING_SNAKE_CASE (KELLY_FRACTION, MAX_POSITIONS, VOLUME_SPIKE_MULTIPLIER)
- Dataframe columns: Match CSV naming convention after loading (date, open, high, low, close, volume)

**Type Hints:**
- Used extensively throughout models/ (Optional, Tuple, List, Dict)
- Return types specified for all public methods
- Parameter types specified for functions taking complex inputs

## Where to Add New Code

**New MDM Signal Detection Feature:**
- Implementation: `models/{feature_name}.py` (e.g., models/new_signal.py)
- Import in: `models/__init__.py` (add to __all__)
- Integration: Add detector instantiation in `models/mdm_engine.py.__init__()`, add processing in `mdm_engine.py.run()` daily loop
- Config: Add parameters to `models/config.py` MDMConfig dataclass

**New VSA Component:**
- Implementation: `vn30_vsa/{component_name}.py`
- Import in: `vn30_vsa/__init__.py` (add to __all__)
- Integration: Import in `vn30_vsa/vsa_engine.py`, call methods in main backtest loop
- Config: Add constants to `vn30_vsa/config.py`

**New Performance Metric:**
- Add calculation method: `models/performance.py` or `vn30_vsa/performance.py`
- Call from: Engine summary methods or analysis scripts
- Report in: Output to notebook or report file

**New Analysis Script:**
- Location: Root directory (analyze_*.py) or `analysis/` subdirectory
- Pattern: Import engine, load results, calculate metrics, print/plot results
- Entry: User executes directly or from notebook

**New Optimization:**
- Location: Root directory (optimize_*.py)
- Pattern: Define parameter grid, iterate configs, run engine, compare metrics
- Framework: Follow `optimize_mdm.py` structure with nested loops and result collection
